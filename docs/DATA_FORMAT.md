# 本地日记文件格式 v1–v3

日期：2026-11-18。此文档对应 `DiaryFileCodec`、`DiaryDocument` 与 `DiaryRepository` 的实现；v1 仅 Markdown，v2 增加可选位置，v3 增加可选天气快照。

## 目录与命名

正常库位于 `~/Library/Application Support/MacDiary/LocalLibrary.noindex/Entries/`，示例库位于同级 `DemoLibrary.noindex/Entries/`。正常库首次打开为空；示例只在显式选择示例模式时生成。开发与性能脚本使用独立的临时目录。

每篇文件名为小写 UUID 加 `.diary.json`。同一天可以有多篇日记，标题和日期均不用于文件寻址。没有持久化的正文搜索索引；启动时重建只含元数据的列表，正文只留在当前编辑会话。

标题搜索只匹配公开标题，忽略大小写与音调符号；日期筛选直接比较记录的 `day`，不把该日期换算为当前设备时区。筛选不会关闭当前编辑会话，列表按自然日分组。

## 废纸篓

`Entries/Trash/UUID.diary.json` 保存可恢复的日记，容器格式仍是 v1。移入与恢复持有同一个库写锁，验证 UUID 与 expected revision 后使用同卷 `renamex_np(RENAME_EXCL)`；已有目标、过期 revision 和不可读源文件均拒绝操作。移动不重新编码，容器字节、UUID、密文和 revision 保持不变。

普通索引与废纸篓索引分开，均只保留公开元数据。废纸篓不打开正文编辑会话；恢复私密日记后仍需解锁。移入前必须先完成自动保存，失败时原编辑会话与草稿保留。已在废纸篓中的 UUID 不能通过新建或旧自动保存重新写入普通目录。

当前不自动清空废纸篓，也不提供永久删除。损坏的废纸篓文件保存在 `Trash/Quarantine/`；未来版本保留原位。备份快照必须明确包含废纸篓，不能仅扫描普通目录；M5 的 `BackupService` 已把 `Entries/` 与 `Trash/` 一并纳入快照，恢复时保持两者的相对位置。

## 容器

```json
{
  "schemaVersion": 1,
  "metadata": {
    "id": "UUID",
    "title": "公开标题",
    "day": "2026-11-10",
    "timeZoneID": "Asia/Shanghai",
    "createdAt": 1794240000000,
    "updatedAt": 1794240000000,
    "revision": 1
  },
  "content": {
    "kind": "plain",
    "payload": { "markdown": "## 正文" }
  }
}
```

这是字段示意。时间点使用 Unix 毫秒数；创建时间规范化到毫秒，避免跨 JSON 往返导致并发校验误报。`day` 是归属自然日，`timeZoneID` 是记录时区；保存和重开不根据设备的新时区重新计算自然日。

`content.kind` 仅允许 `plain` 或 `encrypted`，使用枚举编码，无法同时带有普通正文和密文。普通正文保留原始 Markdown，不把显示时的富文本写回源文件。

`schemaVersion` 当前允许 **1**、**2** 与 **3**。只有 Markdown 的 v1 容器仍然合法；位置是 v2 新增的可选载荷字段，天气是 v3 新增的可选载荷字段。容器版本必须至少覆盖载荷所需的最低版本（`requiredSchemaVersion`）：无位置与天气为 1，带位置为 2，带天气为 3；天气必须与位置同时存在。旧版构建只识别 v1（部分构建识别到 v2），遇到更高版本会保留原文件而不是覆盖，避免静默丢弃位置或天气。位置或天气一旦使用过，清除后容器保持较高版本（不自动降级），以免旧版再次写入时丢失后续扩展字段。

### 位置载荷（v2）

```json
"payload": {
  "markdown": "## 正文",
  "location": {
    "latitude": 31.2304,
    "longitude": 121.4737,
    "horizontalAccuracy": 12,
    "capturedAt": 1760000000000,
    "source": "current",
    "label": "上海"
  }
}
```

- `latitude` / `longitude` 必须在合法范围内；`horizontalAccuracy` 为米且不得为负；`capturedAt` 与元数据时间一致，使用 Unix 毫秒；`source` 为 `current`（单次定位）或 `manual`（地图选点）；`label` 是可选显示地名，坐标与地名分开保存。
- `source = current` 时 `horizontalAccuracy` 是系统报告的定位精度（2026-11-17 实测为 35 m，仅供参考，不承诺 GPS 级精度）；`source = manual` 时没有设备精度，写入 `horizontalAccuracy = 0` 作为“非定位来源”的占位值，读取方不得把它当作精确坐标。
- 私密日记的位置位于加密载荷内，文件头、索引和摘要都不含坐标或地名；锁定后会话不再暴露位置。
- 地图选点与自动定位共用同一坐标模型，只记录来源；地图只在选点时创建，关闭即释放。

### 天气载荷（v3）

```json
"payload": {
  "markdown": "## 正文",
  "location": { "latitude": 31.2304, "longitude": 121.4737, "horizontalAccuracy": 0, "capturedAt": 1760000000000, "source": "manual", "label": "上海" },
  "weather": {
    "temperatureCelsius": 14.4,
    "apparentTemperatureCelsius": 12.9,
    "weatherCode": 3,
    "windSpeedKmh": 8.2,
    "fetchedAt": 1760000189304,
    "source": "Open-Meteo",
    "timeZoneID": "Asia/Shanghai"
  }
}
```

- 天气快照只在按确认坐标请求成功后写入；请求失败、超时或取消不改变已有天气，也不把错误写成天气对象。`fetchedAt` 是请求完成时间（Unix 毫秒），与日记自然日分开，过去日期的日记不会自动获取当前天气。
- `source` 记录数据来源（当前为 `Open-Meteo`）；`timeZoneID` 记录接口返回的时区，便于说明快照对应地点时刻。正文与标题不发送给天气服务商，只发送坐标。
- 天气与位置同在 `DiaryPayload` 内：私密日记的坐标、地名与天气都随正文加密，文件头、索引和摘要不包含它们；锁定后会话清空位置与天气。
- 切换地点会清除旧天气并丢弃在途结果；同一地点的“刷新天气”会生成新的 `fetchedAt`。旧版构建遇到 `schemaVersion 3` 保留原文件，不覆盖。

加密日记的 `payload` 是 `EncryptedDiary`：加密格式版本、同一 UUID、AES-256-GCM、PBKDF2-HMAC-SHA256 的算法/600,000 次参数/16 字节 salt、密码封装的数据密钥、加密载荷。Data 以 JSON base64 编码；原始数据密钥、密码和已解密正文不写入该容器。文件元数据保持公开；加密认证绑定日记 ID 和加密参数，不将公开标题当作私密数据。

当前写作体验采用每篇独立设置密码；每篇使用独立随机数据密钥。一套公共密码管理多篇日记、恢复密钥及修改/移除密码仍属于后续体验范围。

## 写入与并发

1. 在 actor 中串行处理本进程的存储操作；写入和隔离操作还持有库内 `.writer.lock` 的非阻塞进程锁。
2. 新建要求目标不存在；更新要求调用方提供与磁盘一致的 revision，且 UUID、创建时间、自然日和时区保持一致。冲突时保留旧文件并返回错误。
3. 验证完整容器，先写同目录唯一名称 `.pending-UUID` 文件，设为 `0600`，同步并关闭文件，再用同卷 `rename` 原子替换最终文件。
4. 只有替换成功才返回递增 revision。失败时保留原文件、清理本次临时文件，界面继续持有未保存草稿。

库目录创建为 `0700`。这保证正常应用保存过程中的完整文件替换，不宣称能擦除旧磁盘块、旧备份或覆盖强制断电前尚未提交的编辑。

## 自动保存与关闭

编辑采用 350 毫秒防抖。写入尚未完成时继续输入，新一代草稿会在同一保存队列中继续写入；不会用旧快照覆盖新的界面内容。状态区分等待、正在保存、已保存和失败。

切换日记与新建前 flush 当前队列；窗口关闭和退出应用也通过异步保存守卫等待完成。保存失败不切换或关闭，并保留草稿与重试入口。

私密日记的活动正文只在会话内存在；修改后自动保存的是更新过 nonce 的密文。锁定时清除明文及会话密钥引用并重建编辑器实例；重新打开容器必须重新解锁。完整缓存/辅助功能/撤销隔离审计仍按 SEC-005 单独验收。

0.4 起，原生编辑器的标题与正文写回还需匹配当前 `editorIdentity`，旧视图的延迟回调不能修改新会话。编辑器宿主移除时清空原生正文、委托和撤销历史，丢弃未提交的组合输入，释放托管内容；没有启用编辑器 parking。原生探针保留旧 NSTextView 引用检查这些边界，而非只判断新页面是否显示锁头。

密码面板固定绑定打开时的会话和加密 / 解锁模式。空密码、过短密码、确认不一致、会话已切换均不提交；提交与取消清除输入字段。取消进行中的解锁或收到锁定事件会使旧解锁结果失效，避免计算完成后重新显示正文。这些措施不保证 Swift 字符串、系统交换区或已授权复制内容的物理擦除。

## Markdown 导出

导出只包含 UTF-8 Markdown 正文，不加入标题、日期或 front matter。文件名默认包含记录日期和经过清理的标题，用户通过系统保存面板选择位置；取消不会生成文件。

锁定的私密日记不能导出。解锁后面板明确提示将生成未加密正文；确认后先 flush，再次确认会话仍已解锁，并直接写入选定的新 `.md` 文件。若面板打开期间切换了日记或发生锁定，原请求不导出另一篇日记。

导出使用 `O_CREAT | O_EXCL | O_NOFOLLOW` 和 `0600` 权限，不覆盖现有文件或符号链接，也不创建临时明文、恢复草稿、全文索引或其他磁盘缓存。写入报错时清理本次新建的导出文件。强制中断可能留下不完整的选定导出文件；这与日记库的原子保存边界不同，不会修改日记容器。

## 备份快照（M5）

备份目录由用户选择并保存安全书签。快照位于 `备份根/MacDiarySnapshots/snapshot-<UTC 时间>-<UUID8>/`：

```
snapshot-20261117-113837-39557765/
  Entries/<uuid>.diary.json   # 活跃日记容器，原样复制
  Trash/<uuid>.diary.json     # 废纸篓容器，原样复制
  manifest.json               # 清单，不含标题或正文
  COMPLETE                    # 完成标记，内容为 snapshotID
```

`manifest.json` 使用 `formatVersion 1`，每个条目记录 `path`、`uuid`、`isEncrypted`、`schemaVersion`、`byteCount`、`sha256`；`totalBytes` 必须等于各条目之和。快照先写入 `.pending-<UUID>`，全部容器、清单和 `COMPLETE` 完成后原子改名为最终目录；备份期间对库目录 `.writer.lock` 取排他锁，库忙时不生成半成品。保留策略为最近 5 个带完成标记的完整快照，只删除匹配 `snapshot-*` 且校验通过的目录。

恢复前重新校验清单、完成标记、精确文件集合、大小、SHA-256，以及解码后的 UUID、schemaVersion 与是否加密；目标隔离目录必须没有日记文件、`Trash` 为空或不存在。恢复先写 `.restore-<UUID>` 暂存目录，再逐文件移动：`Entries/x` 落到目标目录的 `x`，`Trash/x` 落到目标目录的 `Trash/x`；失败回滚已移动文件。恢复不改写容器字节，UUID、密文与 schemaVersion 1...3 均保留。

2026-11-18 已按上述语义在真实 iCloud Drive 上从应用面板完成端到端恢复：2 活跃 + 1 废纸篓、三个容器 SHA-256 与清单一致、UUID 与 schema 1/3 保留；非空目标被拒绝。

清单和备份目录不写标题、正文、同 ID 索引或搜索缓存。加密日记始终复制密文；普通日记按原有明文状态复制，因此普通日记的备份目录本身仍是明文载体，用户选择备份目录时需知道这一点。

云状态只描述证据：普通目录为 `localOnly`；iCloud 目录中任一文件未上传为 `waitingForUpload`；全部文件经系统确认上传才为 `uploaded`；无法读取属性为 `unknown`。本地写入成功不会自动显示为云端完成。

## 损坏与未来版本

- 普通文件、UUID 与文件名、日期、时区、时间顺序及字段限制均需验证；不沿符号链接读取日记。
- JSON 或已知文档内容损坏时，移入 `Quarantine/随机前缀-原文件名` 并显示未载入提示，原始字节保留。
- 未来 `schemaVersion` 在解析正文前被识别；保留原位，不覆盖或自动降级。权限错误、超限、符号链接等也保留原位并报告。
- 当前最大容器为 16 MiB，普通 Markdown 最大为 8 MiB，标题 UTF-8 最大 4,096 字节；超限不截断原文、不覆盖旧文件。
- v1 没有既有持久化库的迁移需求：M1 的日记只存在于内存。未来格式变化须新增版本及显式迁移测试。

## 0.5 本机 Touch ID 缓存

日记文件与密码封装格式仍为 v1，没有写入指纹、设备数据密钥或 Touch ID 开关。用户用密码解锁后显式启用，按应用 Bundle ID 的服务命名空间与日记 UUID 把 32 字节数据密钥保存到本机受保护 Keychain。索引只查询缓存属性，不自动弹出认证。

缓存使用 biometryCurrentSet 和 ThisDeviceOnly；读取必须取得真实密钥并通过现有 AES-GCM 认证。认证结果与解锁代次关联，锁定会取消 LAContext 并丢弃过期结果。停用只移除本机缓存；废纸篓原样移动保留日记 UUID，恢复后重新查询缓存。更换设备或缓存失效时仍可用原日记密码恢复。

无签名授权的构建关闭 Touch ID 入口，不降级保存成普通 Keychain 密钥。受保护条目的非交互属性查询也可能需要认证；这时只显示认证入口，不能把它当作已读取密钥或已解锁。实际解锁仍需受保护读取和 AES-GCM 校验。真实生物识别验收状态见 [TOUCHID_VALIDATION.md](TOUCHID_VALIDATION.md)。
